# VibeDesign

由当前调用此 Skill 的智能体直接完成设计判断、结构推导和代码生成。使用智能体已有的模型与文件工具，不依赖网页、API Key、本地推理服务或另一个 Codex 进程。

## 按输入选择工作

- **产品调性 / Vibe**：生成设计系统与工程约束。
- **业务代码、数据库 Schema 或 API 数据 + 设计系统**：生成业务页面。
- **两种输入都有**：先确定设计系统，再生成页面，整条链路直接完成。
- **只有业务结构**：优先读取目标项目的既有设计规范；没有时根据业务场景生成适配的设计系统，简要注明采用的风格。

复用对话中已提供的文件与要求。页面类型可为 dashboard、form、landing、list；未指定时按业务目标推断，不把所有数据都套成 dashboard。缺少影响功能的业务定义时，只询问无法从代码推断的部分。

## 生成设计系统

读取 [references/design-contract.md](references/design-contract.md)，按其中的字段生成完整 `design-system.json`。

从用户、业务密度、品牌气质推导色彩、字体、字阶、间距、圆角与阴影。避免把每个项目都做成同一种极简灰色界面；现有品牌资产和用户明确的视觉方向优先。

设计令牌需要可直接使用：字体提供回退栈，尺寸与阴影采用合法 CSS 值，字阶给出实际字号序列，容器内边距与生成页面保持一致。不要只用“高级感”“数学级”描述结果。

生成后执行技能目录中的检查脚本：

```sh
python3 <技能目录>/scripts/check_contrast.py <产物目录>/design-system.json
```

它计算四组正文颜色对比度；失败时调整色值并重跑。该结果仅证明检查过的颜色配对达到正文 4.5:1 阈值，不代表整页已通过 WCAG。若业务约束不允许修改配色，说明具体冲突。

将同一份令牌转成目标工程的样式配置与 `.cursorrules`：规则必须引用实际颜色、尺寸、字阶和组件状态，避免空泛形容词。Tailwind CSS 3 输出 `tailwind.config.ts`；已有 Tailwind CSS 4 工程使用其 CSS 主题变量方式，不为了套用模板降级依赖。非 Tailwind 项目沿用其现有样式体系。

## 从业务结构生成页面

读取用户提供的代码与相关调用点，识别实体、字段、枚举、关联、状态和真实操作。先给出简短的 `uxAnalysis`，说明业务字段如何决定交互，再实现页面。

- 枚举映射为 select、radio 或适当筛选控件；布尔值映射为带标签的 checkbox / switch；时间使用 `Intl.DateTimeFormat`；多条记录采用列表或表格。
- 按任务组织字段与操作，不把每一个后端字段都机械展示为输入框。布局与视觉层级服务于主要任务。
- 使用设计系统中的语义颜色、圆角、内边距、阴影和字阶；保持默认、悬停、聚焦、禁用、错误状态一致。
- 复用已有组件和依赖；独立 Next.js 页面使用完整单文件、默认导出，有客户端交互时加 `"use client"`。Lucide 图标仅在已安装或用户要求时使用，避免引用不存在的组件。
- 已有业务 API 时接入真实逻辑；只提供数据结构时可用清楚标注的模拟数据完成交互。保存、筛选、分页等可见操作必须实现或明确禁用，不留空处理函数冒充完成。
- 为表单关联 label，为图标按钮提供名称，保留键盘焦点，并覆盖适用的空数据、错误与加载状态。

## 产物与验证

用户指定目录时按其位置交付；未指定时，在当前项目的 `vibedesign-output/` 保存产物。请求直接修改现有页面时，按项目结构实施。已有文件要先读取，合并相关修改。

设计系统任务交付 `design-system.json`、适配工程的样式配置及 `.cursorrules`。页面任务额外交付实际 React 源文件和简短交互分析；用户只要页面时不重复生成已有规范。若调用方明确要求结构化返回，设计任务返回 `{ designSystem, artifacts: { cursorRules, tailwindConfig } }`（Tailwind 3），页面任务返回 `{ uxAnalysis, reactCode }`；否则优先交付文件链接，避免贴长 JSON。

用目标工程已有的构建、类型检查与适用的交互测试验证代码；有浏览器工具时检查页面。缺少运行环境时报告未验证项，不把模型生成的代码称为已编译。不要为了使用 Skill 创建“输入提示词→调用另一个模型”的网站或后端。
